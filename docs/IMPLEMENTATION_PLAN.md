# 実装ロードマップ

## 進め方

M0 → M1で「入力→TeX→実PDF表示」を動かし、M2以降で書類の内容と保存を増やす。最初に大きなエディタを作らず、macOSのWebViewと外部TeXの連携を検証する。

各タスクは1つのPRとしてレビューできる規模に分割する。工数はM1の結果を見て見積もり、現時点で納期を固定しない。

## 設計リスクと解消地点

| リスク | 解消方法 | 地点 |
| --- | --- | --- |
| 編集画面とPDFの組版差 | 本文WYSIWYGと実PDFプレビューを仕様で分ける | M1 |
| GUIのPATH・TeX依存 | bundle起動から診断・実コンパイルする | M1 |
| macOSの自動E2E | embedded方式を小さくCIで実証する | M1 |
| TS/Rust間のモデルずれ | Schemaと共通fixture、IPC契約検証 | M2 |
| 長文・リストの改ページ | 上限fixture、抽出・ログ検査、PDF目視 | M4 |
| latexmk配下の子プロセス残留 | 実プロセスで中断・タイムアウトを検証 | M5 |
| CIがTeXを検証していない | 実TeXジョブをスキップ不可の必須ゲートへ | M6 |
