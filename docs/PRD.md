# PRD：履歴書・職務経歴書生成エンジン

- 状態：初稿／実装前
- 作成日：2026-10-05
- プロダクト名：Resume Studio（仮称）
- 対応範囲：macOS先行、ローカル専用デスクトップアプリ

## 1. 目的

LaTeXの記法を意識せずに日本語の履歴書・職務経歴書を作成し、統一されたテンプレートで提出用PDFを出力できるようにする。編集データはJSONで保持し、書式変更やテンプレート追加の際にも内容を再利用できるようにする。

少ない依存と明確な責務分離で、小さく実装して育てられる構成を目指す。GitHub上で再利用できるTauriアプリのテンプレートにもする。

## 2. 利用者と主要フロー

対象は、日本語で応募書類を作成し、自分のPC上で編集・保管したい利用者。

1. 新規プロジェクトを作り、基本情報を入力する。
2. 履歴書の学歴・職歴・資格、職務経歴書の職務要約・職務詳細・スキル・自己PRを編集する。
3. テンプレートを選択し、PDFを生成して紙面を確認する。
4. 必要に応じて修正し、PDFまたはTeX一式を出力する。
5. JSONを保存し、アプリを再起動した後も編集を続ける。

### WYSIWYGの定義

本文の書式は編集画面に即時反映する。履歴書の固定項目はフォームまたは編集可能な表として入力する。改ページ、罫線、余白、フォントによる厳密な紙面確認は生成済みPDFで行う。

MVPではPDFの文字を直接クリックして編集する機能、任意の位置へのドラッグ配置、HTMLとTeXの組版の完全一致は対象外。この定義はスピードを優先する初期案であり、紙面を直接編集する要件がある場合はM1前に見直す。

### テンプレートの初期仕様

- 履歴書：A4縦、原則2ページの独自レイアウト。学歴・職歴の行数が多い場合は継続ページを生成する。
- 職務経歴書：A4縦、内容に応じた複数ページ。長い職務詳細はページをまたげる。
- 履歴書を含め、特定規格への準拠は表明しない。
- 日本語・英数字混在、写真あり／なし、空の任意項目、複数ページを扱う。
- 入りきらない固定欄は警告し、継続領域で内容を表示する。黙って切り捨てたり過度に縮小したりしない。
- データ、対応書式、使用フォント、必要TeXパッケージ、テンプレート版を明記する。

## 5. 非機能要件

| ID | 要件 | 検証方法 |
| --- | --- | --- |
| N01 | オフラインで編集・保存・生成でき、個人情報を外部へ送信しない | ネットワークを切ったmacOSで主要フローを完了 |
| N02 | 通常入力で編集操作をブロックしない | 10ページ相当のサンプルで操作を確認。PDF生成は非同期 |
| N03 | 保存失敗で既存JSONを破損させない | 一時書込→置換方式と失敗注入テスト。失敗時も未保存状態を保持 |
| N04 | 同一入力・同一テンプレート版でTeXが安定する | ゴールデンテスト。PDFバイナリ一致は要求しない |
| N05 | 日本語IME、キーボード操作が成立する | 実macOSで変換確定、Undo/Redo、保存ショートカットを確認 |
| N06 | 長時間コンパイルから回復できる | 初期タイムアウト60秒、キャンセル、子プロセス停止のテスト |
| N07 | 古いPDFを最新結果と誤認しない | 編集リビジョンを表示し、古い生成結果が後から上書きしない |
| N08 | CIで品質ゲートを自動実行する | TypeScript型チェック、Oxlint/Oxfmt、Rust check/clippy/fmt、結合テスト |

数値は初期の検証条件。生成時間はTeX環境に依存するため、M1でコールド／ウォームの実測値を記録し、MVPでは時間の一律SLAを設けない。

## 6. 対象外

クラウド同期、ログイン、AIによる本文生成、共同編集、Word入出力、既存PDF取込、多言語テンプレート、TeX自動インストール、任意TeXの直接実行、UIでのテンプレート制作、署名・公証・自動更新、Windows/Linuxの正式サポート。

自動PDF生成とクラッシュ後の下書き復旧も後続とする。MVPのPDF更新は手動操作、JSON保存は明示操作。

## 7. MVP完了条件

架空の日本語データで、編集→JSON保存→再起動→読込→両書類のTeX/PDF出力を実macOS上で完了する。写真と本文書式が維持され、日本語の文字化け・欠落・重要な組版崩れがない。

空データ、長文、TeX特殊文字、壊れたJSON、TeX未検出、コンパイル失敗、保存失敗、タイムアウトに対応する。CIで必須ジョブが通り、第三者がREADMEを使ってセットアップできる。
