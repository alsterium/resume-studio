# 書類別TeX bundle

正式Projectは検証後、履歴書／職務経歴書の書類モデルに変換し、選択された同梱テンプレートで`GeneratedBundle`を生成する。入力テキストは共通エスケープ、本文は限定AST visitorを通す。入力をTeX命令として評価したり、テンプレートへの文字列置換を行ったりしない。

## 出力契約

- `main.tex`：固定の入口。LuaLaTeX、ltjsarticle、luatexja-preset（Harano Aji）で`content.tex`を読み込む。
- `content.tex`：書類の項目を固定マクロへ渡す。履歴書は基本情報・2連絡先・学歴／職歴／資格の行・志望動機・希望欄、職務経歴書は氏名・日付・要約・スキル／職務経歴書用資格・会社／案件の全項目・自己PRを出力する。配列順を保持する。
- `resume.sty`または`career.sty`：紙面・項目の組版定義。履歴書はT18の罫線帳票。職務経歴書はT19の見出し・灰色帯・2列スキル表。最大長などの境界検証は下記T20の検証マトリクスを参照。
- `manifest.json`：テンプレートID・版・表示名・書類種別・対応Schema・エンジン・必要パッケージ／フォント。
- 履歴書だけ、選択写真を正規化して`photo-1.png`または`photo-1.jpg`へ展開する。未選択写真や元画像パス、Projectの管理用ID／titleは紙面へ出さない。

同梱版は`resume-standard`の`1.2.0`／`1.1.0`／`1.0.0`と`career-standard`の`1.1.0`／`1.0.0`、Schema 1、LuaLaTeX。ID・版・書類種別・Schemaの完全一致で解決し、非対応なら`TEMPLATE_NOT_FOUND`として拒否する。JSONの指定版を自動変更しない。画面の「テンプレート一覧を確認」から利用可能な版を明示選択すると未保存変更になる。

履歴書の年齢は書類日付時点で計算。未入力の年月・任意欄は空欄。職務経歴の終了年月nullは在籍中／進行中、空文字は空欄を保持する。空の任意会社項目・案件本文／URL・自己PRは見出しごと省略する。URLはHTTP(S)として検証してリンク先を正規化・エスケープし、表示の各文字間に折返し候補を入れる。リンク先には折返し命令を入れない。

## 履歴書の帳票と続紙

現在の既定1.2.0は[TEMPLATE_REFERENCEのT35仕様](TEMPLATE_REFERENCE.md#8-参照原本への再調整t35)に従う。本文11.25pt、行高9.5mm、氏名15.75pt、左右／上下18mm、30×40mmの写真に枠線なし。1ページ目16行、2ページ目の経歴・資格各6行と同高の自由欄。日本語はscale=1とRegular／Boldを明示する。以下は旧1.1.0の仕様で、旧JSONの出力を保持する。

履歴書1.1.0はA4・左右18mm／上下16mm、本文10.5ptのゴシック体、ページ番号なし。1ページ目には書類日付、氏名・ふりがな・生年月日・満年齢・任意性別、右上の30×40mm写真枠、住所／電話・メールの2列を配置する。写真は縦横比を保持する。別連絡先と未選択の写真枠は空欄でも残す。

学歴と職歴は一つの年／月／内容表にまとめ、区分行と右寄せの「以上」を付ける。1.1.0の列幅は年18mm／月10mm／残りが内容、外枠0.45pt、行罫線0.25pt。年・月の間とふりがなの下は点線とする。2ページ目は学歴・職歴の続き、免許・資格、志望動機、本人希望欄の順に配置する。

`ResumeFinish`が各欄の測定済み行を消費して通常の2ページを組む。履歴行・本文を巨大な一体の表セルにせず、TeXの行単位で分割できる縦リストに保持する。複数行の履歴の途中でも分割でき、年月はその行の先頭に表示する。空き領域は空行を補う。

1.1.0の行高は7.5mm。1ページ目は連絡先までをページビルダーに確定し、残り高さから18mmを引いて履歴領域を伸縮する。2ページ目は履歴37.5mm・資格45mm、志望動機90mm・希望60mm。見出し高は別に加算する。旧版1.0.0の寸法・出力は維持する。寸法の変更は`resume.sty`の設定マクロで行い、JSONに組版用の値を持たせない。

通常欄に収まらなかった内容は、基本の2ページの後へ基本情報・連絡先→学歴・職歴→免許・資格→志望動機→本人希望の順に続紙を追加する。切り捨てない。PDF.jsで読み取った実ページ数が2を超える履歴書にだけ、プレビューで続紙の確認を促す。下書き・職務経歴書にはこの警告を出さない。

基本情報の組版結果が80mm、各連絡先が55mmを超える場合は固定枠に「続紙に全文を記載」と表示し、値を丸ごと続紙へ移す。続紙は10.5ptの本文で行単位に分割し、写真は最初のページの枠へ残す。氏名等を切り捨てたり極端に縮小したりしない。

長大な本文の箱はTeXの寸法上限を超える場合があるため、LuaTeXから高さ・深さを読み、固定高さで分割する。参照は読み取りだけで、分割・箱の所有権はTeXが管理する。[LuaTeX Reference Manualのbox register API](https://tex.org.uk/systems/doc/luatex/luatex.pdf)に従う。

入力はProject JSONの制限に従い、生成後の`content.tex`は64MiB以内（超過はエラー、切り捨てなし）。bundleの書込は呼出側が所有する新規作業ディレクトリで行う。資源名は固定の許可リストに限定し、重複・既存ファイル／symlinkは書込前に拒否、各ファイルはcreate_newで作成する。途中のI/Oエラーでは作業ディレクトリ所有者が片付ける。コンパイル時はTempDirが成功／失敗双方を片付ける。利用者向け保存・上書き確認は現在のsnapshotから行い、書類別に結果を返す。保存失敗と復元の対処は[TROUBLESHOOTING](TROUBLESHOOTING.md)を参照。

## 職務経歴書の流し込み

現在の既定1.1.0は案件名と期間を同じ行にし、本文ラベルを通常ウェイト、会社名12pt、セクション13.5ptとする。本文はscale=1のRegular。旧1.0.0を保持する。

A4・余白18mm、本文10.5pt／行送り17ptのゴシック体、ページ番号なし。18ptの書類タイトルに二重線を添え、日付・氏名を右寄せする。セクションは1.1.0で13.5pt（旧1.0.0は14pt）太字と全幅の下線、会社名・期間は薄い灰色の帯、案件は白抜き菱形と太字の名称、期間は小さな灰色文字で階層を表す。

スキル・職務経歴書用資格はほぼ等幅の2列に配置する。資格はcareer.qualificationsを使用し、右列の年月は「N年M月 取得」とする（未入力は空欄）。左列は太字の名称と任意の経験期間、右列は灰色の説明。横の点線で行を分け、外枠と縦罫線は付けない。長いセルは35mm以下の断片へ分割して改ページできる。色は断片ごとに適用し、後続の本文へ漏らさない。

会社の案件がある場合だけ「主な実績」を出す。案件は概要→担当フェーズ→業務内容→実績・取り組み→規模→言語→技術→URLの順。会社や案件全体を分割不能な箱にせず、本文は段落・行単位で改ページする。見出し前には後続数行分の空きを確保する。自己PRが空なら見出しも省略し、空の末尾ページを増やさない。

通常・空の架空fixtureは1ページ、長いスキル説明／案件本文／自己PR／区切りのないURLは複数ページになる。実PDFから全文・順序・A4寸法・各行のリンク先を検証し、欠字・はみ出し警告と孤立見出しを検査する。写真の配置は履歴書だけに適用する。最大長は下記T20の検証マトリクスで確認する。

## T20の検証マトリクスと目視QA

| 入力 | 実PDFで確認する内容 |
| --- | --- |
| 空／通常の両書類 | 履歴書2ページ・職務経歴書1ページ、A4、本文・写真の有無 |
| 各固定文字列1024文字 | 基本情報・連絡先・履歴3種・スキル3項目・会社と概要・案件名／規模／一覧値の全文、長い英数字の折返し |
| 案件URL2048文字 | 表示の全文保持。長いリンクの各行のリンク先はT19の実annotation検証と併用 |
| 本文64KiB | 日本語・空白なし英数字それぞれの要約／志望動機を両書類へ組版し、ページをまたぐ全文を比較 |
| 書式が分割された英数字 | 隣接する太字／斜体text node間でも連続した語を折り返し、全1024文字を保持 |
| 写真なし／PNG縦長／透過PNG正方形／JPEG横長 | 2ページの維持、画像の有色画素の位置と物理寸法・縦横比、空の写真枠 |

12文字以上連続する表示用ASCIIには折返し候補を入れる。短い文字列と日本語の通常組版は保持し、エスケープだけを担う関数はURLのリンク先や資源名へ使用する。本文では段落内の連続文字をmark境界をまたいで判定する。長いTeXソース行はコメント付き改行で分け、紙面に空白や段落を追加せずにTeXの入力バッファ上限を避ける。

文字抽出では履歴表の繰り返し見出しを除き、左右のスキルセルはPDFKitの領域別抽出で照合する。列や見出しが抽出順へ混ざることを文字の欠落と混同しない。全ケースでA4寸法、欠字とOverfull警告を確認する。最大長は各項目の上限を検証するマトリクスであり、全会社・全案件を最大件数と最大本文長で同時に埋めた組合せの生成成功を保証しない。JSON／生成量／PDF容量／コンパイル時間の上限は別途適用し、超過は明示的なエラーにする。

QA出力は架空fixtureからだけ作る。macOSで次を実行すると、最大長と写真ケースの独立bundle・PDFを新規ディレクトリへ保存できる。同じディレクトリ名を再利用すると上書きを拒否する。

```sh
RESUME_STUDIO_PDF_QA_DIR=/tmp/resume-layout-qa pnpm test:tex
pnpm pdf:render /tmp/resume-layout-qa/maximum-fields-Resume/main.pdf /tmp/resume-layout-qa/maximum-fields-Resume/rendered
```

レンダラーはNode.jsからmacOS PDFKit（Swift）を起動し、各ページPNGと4ページずつの一覧画像を生成する。PythonやPopplerは不要。各ページ画像で細部、一覧画像で改ページ・配置・余白を確認する。既存出力ディレクトリには書き込まない。QA PDF／画像はGitへ追加しない。

## 単体コンパイルの確認

開発用exampleはJSONから**新しい**ディレクトリへbundleを展開する。既存ディレクトリへの上書きは行わない。

```sh
cargo run --manifest-path src-tauri/Cargo.toml --locked --example project_to_tex -- tests/fixtures/project-full.json resume /tmp/resume-bundle
cd /tmp/resume-bundle
latexmk -norc -lualatex -interaction=nonstopmode -halt-on-error -latexoption=-no-shell-escape main.tex
```

職務経歴書は`resume`を`career`へ変えて別の新規ディレクトリを指定する。Rust結合テストは正式全項目・書式・版拒否・写真資源・実FS保存を検証し、`pnpm test:tex`は空／全項目の両書類をアプリと同じ隔離コンパイルと展開後の単体コンパイルで確認する。実macOS E2Eは保存・再起動後の両書類を画面操作から生成し、実PDFの文字とPDF.js描画を確認する。

T45のtodayモードは生成・書き出し時の端末ローカル日付を解決し、履歴書・職務経歴書の書類日付に使う。履歴書の満年齢も同じ日付で計算する。fixed/省略は保存された指定日を使う。
