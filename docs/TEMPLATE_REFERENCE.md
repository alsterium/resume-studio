# 標準テンプレートの参考書式

## 1. 方針と観察範囲

利用者指定のローカルPDFを全7ページ、画像として確認した。1〜2ページが履歴書、3〜7ページが職務経歴書。志望動機は履歴書の欄に含まれ、独立した志望理由書ページは確認できない。

標準テンプレートはこの書式に近づける。書類の構成、罫線、見出し、余白、情報の階層を再現し、個人の氏名・写真・連絡先・経歴本文はfixtureやリポジトリに収録しない。元PDFと確認用画像もリポジトリに同梱しない。

以下の寸法は画像からの概算を基にした実装初期値であり、元PDFの厳密な座標・フォント測定値ではない。生成サンプルをレンダリングして調整する。原本は約595×842ptで、A4縦相当。

## 2. 共通の紙面

| 要素 | 観察した特徴 | 実装初期値 |
| --- | --- | --- |
| 用紙 | A4縦、白背景 | A4、210×297mm |
| 本文領域 | 左右・上下に余白、幅広い本文 | 左右18mm、上下18〜20mm |
| 書体 | 日本語ゴシック系、本文は黒〜濃灰 | TeX環境のHarano Aji Gothicを候補に固定 |
| 本文サイズ | 読みやすい密度、職務経歴書は行間に余裕 | 10.5〜11pt、行送り16〜18pt |
| 色 | 黒、濃灰、薄灰。装飾色なし | 白黒印刷で階層が判別できる濃度 |
| ページ番号 | 目視範囲では番号なし | 標準ではページ番号を表示しない |

## 3. 履歴書：罫線付き2ページ

### 1ページ目

上部左に字間を空けた「履 歴 書」、その右に書類日付と「現在」。右上に縦長の証明写真。写真はおおむね30×40mmを初期値とし、アスペクト比を維持して枠内に収める。

氏名ブロックには、ふりがな、名前、生年月日、満年齢、任意の性別表示を置く。名前は本文より大きくする。年齢は書類日付時点で計算し、生年月日とは別入力にしない。性別は未入力を許可し、文字列の表示とする。

次に、住所ふりがな、郵便番号・現住所を左の広い欄、電話・メールを右の狭い欄に配置する。その下に任意の別連絡先を同じ構造で置き、未入力時も空の欄を維持する。

下部は「年／月／学歴・職歴」の3列の表。列幅の初期値は12%／8%／80%。年と月は中央揃え、本文は左揃え。学歴・職歴の区分行は中央、終端の「以上」は右揃え。外枠はやや太い実線、行罫線は細い実線、年と月の間やふりがな区切りは点線。

### 2ページ目

上から順に次の領域を配置する。

1. 学歴・職歴の継続表。通常データで続きがなくても空行を表示する。
2. 「年／月／免許・資格」の3列の表。終端に「以上」、残りは空行。
3. 「志望動機・特技・アピールポイントなど」の罫線付き本文欄。
4. 「本人希望欄」の罫線付き本文欄。補足説明は小さめの文字。

通常の入力量は2ページで収める。表の初期配分は1ページ目16行程度、2ページ目の継続6行程度、資格6行程度を目安に試作する（見出し行を除く）。行数はテンプレート設定に置き、長い行は折り返して必要な高さを確保する。見た目の行数より全文表示を優先する。

学歴・職歴の余剰は継続表へ送り、さらに必要なら追加の継続ページを作る。資格・志望動機・本人希望も超過時は本文を欠落させず継続ページへ送り、プレビューで警告する。追加ページの順序は履歴書本体2ページの後、学歴・職歴→資格→志望動機→本人希望とする。

## 4. 職務経歴書：見出し＋表＋会社／案件

### 冒頭とセクション

左上に太字の「職務経歴書」と二重の横線。その下の右側に書類日付、氏名を縦に配置する。本文は次の順序とする。

1. 経歴要約
2. 活かせるスキル・経験
3. 職務経歴
4. 自己PR

セクション見出しは太字で本文より大きく、下に全幅の細い横線を置く。初期値はタイトル18pt、見出し14pt。見出し直後に十分な本文が置けない場合は見出しごと次ページへ送る。

### スキル・経験

2列の一覧。左に技術名・実務経験年数・資格名などの短いラベルを太字、右に説明を濃灰で表示する。列幅は概ね1:1、行間は薄い点線。外枠や縦罫線は表示しない。

スキルと資格を別の入力配列として保持しても、このセクションでは同じ2列書式で続けて表示できる。経験年数はラベルに埋め込まず任意の独立フィールドとし、本文ラベル生成時に組み合わせる。

### 会社と案件

会社単位で薄灰の全幅帯を置き、左に太字会社名、右に在籍期間。在籍中の表示を扱う。帯の下に事業内容・資本金・従業員数など任意の会社概要を置く。

各会社の「主な実績」の下に案件を順番に表示する。案件見出しは中抜き菱形の記号、太字案件名、やや小さく濃灰の期間。チェック記号や菱形はTeXで描画するか対応フォントで表現し、欠字を避ける。

案件の構成は次の通り。未入力の任意項目は見出しごと省略する。

- 【プロジェクト概要】：本文
- 【担当フェーズ】：設計・開発・テストなどの短い表示
- 【業務内容】：箇条書き
- 【実績・取り組み】：箇条書きまたは段落
- 【プロジェクト規模】：チーム規模など
- 【使用言語】：言語一覧
- 【使用技術】：フレームワーク・ツールなど
- URL：任意の参照先

案件詳細は複数ページをまたいでよい。会社全体や案件全体を改ページ禁止の箱に入れない。会社帯・案件見出し・小見出しの孤立は避ける。元PDFのページ境界は固定しない。URLは紙面幅で折り返し、任意のhttps/httpリンクとして出力可能にする。

自己PRは入力がある場合、最後に同じ見出しと下線を置き、複数の段落で表示する。空の場合は見出しごと省略する。

## 5. データ・エディタへの反映

| 対象 | 追加・具体化する入力 |
| --- | --- |
| 基本情報 | 住所ふりがな、任意の性別表示、別連絡先（郵便番号・住所・ふりがな・電話・メール） |
| 年齢 | 生年月日と書類日付から算出。閏年と誕生日境界をUnitテスト |
| スキル | 技術名、任意の経験期間表示、説明 |
| 職務経歴 | 会社単位の在籍期間・役職・会社概要と、複数の案件 |
| 案件 | 名前、期間、概要、フェーズ、業務内容、実績、規模、言語、技術、URL |
| 編集 | 会社・案件・スキルの追加／削除／並べ替え。長文項目は既存の限定WYSIWYGを利用 |

URLは専用入力欄で扱い、本文の任意リンクmark対応は後続のままとする。履歴書と職務経歴書の資格の共用はプロジェクト内の同じ資格データを参照し、二重入力を避ける。

## 6. 受け入れと検証

- 架空データで通常の2ページ履歴書と複数ページ職務経歴書を生成し、上記の領域・順序・罫線・灰色帯・太字・下線を確認する。
- 原本の本文や写真を使う画像snapshotは作らない。架空サンプルから生成したPDF／画像を視覚回帰の基準にする。
- 通常データ、長い住所、長い学校名、多数の学歴・資格、長文案件、長いURL、写真なしを検証する。
- PDFの文字抽出で末尾の目印まで存在すること、欠字・大幅なはみ出しがないことを確認する。
- 設計上の寸法を守るだけでなく、実際にPDFを画像化して紙面の近さを確認する。元PDFとのピクセル完全一致は要求しない。

TeXテンプレート実装と生成サンプルの確認はM4で行う。履歴書の帳票・続紙はT18で実装し、具体的な寸法と検証範囲を[TeX出力契約](GENERATED_TEX.md#履歴書の帳票と続紙)に記録する。職務経歴書の見出し・灰色帯・スキル表と長文改ページはT19で実装し、[TeX出力契約](GENERATED_TEX.md#職務経歴書の流し込み)に記録する。最大長などの境界検証はT20で行う。
